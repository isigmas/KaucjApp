# AGENTS.md – KaucjApp 3.0

This file applies to every agent (and human) working in this repo. Production branch: `kaucjap-three-dot-zero-prod-by-maxxx`.

## Core principles

Every change must satisfy all three principles. If a change breaks any of them, it is not done.

### 1. Production-grade

- The backend runs on a single VPS (Docker Compose, `deploy/compose.prod.yaml`). We do not go back to Azure managed services.
- No `latest` image tags. External images (Postgres, Kafka, Redis, Caddy) are pinned to a version; our own images are tagged `:<git sha>`.
- Every container has: `restart: unless-stopped`, a healthcheck, a memory limit (`mem_limit`) and log rotation (`json-file` with `max-size`/`max-file`).
- Only ports 80/443 (Caddy) and 22 (SSH, key-only) are exposed publicly. Postgres, Kafka, Redis and the services never publish ports on the host.
- No secrets in the repo, in images or in logs. The only source of secrets is the GitHub Environment `production`. The `.env` file on the server is generated by CI (`chmod 600`).
- Database schema changes go through Flyway migrations only (`src/main/resources/db/migration`). Migrations must be backward compatible (expand/contract), because deploys auto-rollback to the previous images while the database is not rolled back.
- `spring.jpa.hibernate.ddl-auto=validate` stays. Hibernate never creates tables.

### 2. Zero toil (automation)

- Nothing is done manually on the server. Deploys, backups, OS updates, log rotation, image cleanup and alerting all have automation in the repo (GitHub Actions, systemd timers, `deploy/scripts/`).
- A new operational feature (new service, new database, new Kafka topic) is not finished until it is added to: `deploy/compose.prod.yaml`, `deploy/.env.example`, the image workflow, the smoke test, and backups (if it holds data).
- Dependencies are updated by Dependabot. The server patches itself (`unattended-upgrades`).
- Scripts must be idempotent (running twice gives the same result) and fail loudly (`set -euo pipefail`).
- If a "do this by hand" step appears, treat it as a bug to automate, or document it in `deploy/README.md` as a one-time step with justification.

### 3. No loss of functionality

After every change, everything below must work exactly as before:

- `gql-gateway` routes: `/api/user/**`, `/api/offer/**`, `/api/auth/**`, `/api/deposit/**`, `/api/notification/**`, `/api/monitor/**` and `/graphql` (HTTP + WebSocket).
- Kafka flows: user registration and sync, account deletion, completed offers (stats), emails (welcome, password reset, admin) via Resend, and system logs (`system-logs`) persisted by `monitor`.
- Profile pictures (upload via presigned URL to S3/R2, confirm, delete).
- API contracts used by the mobile app (`mobile/KaucjApp`) and the `scripts/deposit_machines_processing` script. Do not change field names or error codes without updating the client.
- Before merging, `cd backend && ./mvnw test` and the compose smoke test (`docker compose -f compose.yaml -f compose.cicd.yaml up --build -d --wait`) must pass.

## Production architecture

Caddy (HTTPS, Let's Encrypt) → `gql-gateway` → services over the Docker network (`http://<service>:8080`). Shared components: one Postgres (a separate database per service: `users_db`, `offers_db`, `auth_db`, `deposit_db`, `notification_db`, `monitor_db`), one Kafka (KRaft), one Redis (auth uses DB 0, gateway uses DB 1). Profile pictures: Cloudflare R2 (S3 API). Images: GHCR.

Spring services are built as GraalVM native images (`backend/Dockerfile.native`, build arg `SERVICE_NAME`). `monitor` is a regular fat JAR (`backend/monitor/Dockerfile`).

## Commands

```bash
# backend tests
cd backend && ./mvnw test

# full environment locally (needs backend/.env with DB_USER, DB_PASSWORD, JWT_SECRET, ...)
cd backend && docker compose up --build -d --wait

# smoke test, same as CI
cd backend && docker compose -f compose.yaml -f compose.cicd.yaml up --build -d --wait

# production deploy: merge to main -> GitHub Actions (images -> deploy). Manually only:
gh workflow run deploy.yml -f image_tag=<sha>
```

## Conventions

- All code, comments, documentation and commit messages are written in English.
- Kafka topics (1 partition, 1 day retention): `notification.mail.welcome`, `notification.mail.resetpassword`, `notification.admin`, `system-logs`, `users.sync`, `users.delete.command`, `users.deleted.event`, `offers.completed`. A new topic is added to `deploy/kafka/topics.txt` (used by both dev and prod).
- Configuration through Spring-style environment variables (`SPRING_DATASOURCE_URL`, `SPRING_KAFKA_BOOTSTRAP_SERVERS`, ...). No environment-specific values in `application.properties`.
- Native services must not rely on reflection without hints (see `DtoRuntimeHints`). Register new DTOs in the hints.
- Never commit `.env` files, `application-local.yml` or any tokens. The git remote URL must not contain a token.
